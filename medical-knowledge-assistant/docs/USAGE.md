# 使用说明

## 启动与停止

按仓库 README 安装依赖及创建本地 `.env`。VS Code 打开仓库根目录后，“任务: 运行任务”中提供“启动后端”“启动前端”“启动前后端”和两项本地回归任务。

后端应显示 Uvicorn 正在监听 8000；前端开发服务使用 3000。打开 `/health` 返回 healthy 仅表示本地后端正常，不代表模型已连通。

在各自任务终端按 `Ctrl+C` 停止。修改后端代码或 `backend/.env` 后重启后端；前端 `npm start` 支持源码变更自动编译。改变前端 `.env` 后也应重启前端。

## 图谱查询

1. 打开 `/knowledge`。
2. 搜索“高血压”或“糖尿病”，点击查询。
3. 将关系深度调为 1，查看较清晰的局部关系。
4. 拖动画布或节点，使用滚轮及放大、缩小按钮查看关联。

最多显示 300 个节点，页面统计代表当前局部图；完整图谱总量通过 `/api/knowledge_graph/statistics` 查看。节点点击会更新右侧选中实体。要切换查询中心，重新输入名称查询；当前未实现双击节点自动展开。

图谱采用现有实体名称和字符串匹配，没有成熟的模糊实体链接或向量检索。查不到时先核对准确名称。图谱查询可以在没有模型密钥时独立使用。

## 智能问答

先手动输入“仅用于系统连通性测试，请回复连接成功”，点击发送。页面欢迎语来自前端，不能用于证明真实模型连通。

再输入包含图谱实体的合成问题，观察回复。后端默认启用 `use_kg`，提取最多 30 条关系加入模型上下文；普通接口的 `sources` 返回本地来源标记，标记不是医学文献引用。

“停止生成”取消前端读取，不保证上游请求与计费立即结束。“保存对话”将会话存入当前浏览器 localStorage；“历史记录”查看已保存会话；“清空对话”重置当前会话，不等同于删除全部历史。同一浏览器也应保持访问地址一致，localhost 和 127.0.0.1 属于不同站点。

不要将输出作为诊断、处方或治疗依据。示例测试使用合成内容，不需要上传真实病历或个人健康资料。

## 模型配置

本地编辑 `backend/.env`。当前默认提供方为 `baidu`，实际模型由 `DEFAULT_LLM_MODEL` 指定。密钥填写完整原值，SDK 自动添加 Bearer 前缀。不要把 `.env` 提交到 Git。

可使用 `DEFAULT_LLM_PROVIDER=openai` 并填写 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、对应的 `DEFAULT_LLM_MODEL`，切换到另一套 OpenAI 兼容配置。此分支存在于代码中，本轮未完成其他服务商的真实验证。

原项目曾使用 `ernie-4.5-8k-preview`，上游返回 401 及 `invalid_model`；已换为 `ernie-4.5-turbo-128k`。服务列出模型不等于账号必然有权限。项目已有真实回复证据，但仍曾出现连接失败，演示前应再次检查。

## 常见错误

| 提示 | 处理 |
|---|---|
| `invalid_model` | 模型不存在或当前账号无权访问；核对模型名称与权限，不能只因 HTTP 401 就认定密钥失效 |
| API 密钥未配置 | 在 `backend/.env` 填写密钥，再重启后端 |
| 模型服务认证失败 | 检查完整密钥、有效性及服务权限 |
| 无法连接模型服务 | 检查到模型地址的网络、代理及 TLS 连接，不通过关闭证书校验解决 |
| 模型服务额度不足或请求频率受限 | 检查额度与限流信息，避免连续重复发送 |
| 模型服务响应超时 | 检查网络及上游状态，图谱仍可独立使用 |
| 地址已被使用 / WinError 10048 | 检查是否同时运行原工程或重复启动同一个 8000 服务 |
| 修改配置没有生效 | 重启后端；系统环境变量可能优先于 `.env`，检查是否保留旧值 |
| 图谱过于拥挤 | 降低关系深度或调整缩放；300 节点限制不代表全量数据被截掉 |

## 调试和验证

先停止占用 8000 的后端任务，然后在 VS Code F5 选择“调试后端”。解释器选用仓库 `.venv`。

两项回归任务不需要真实模型密钥：图谱测试覆盖数据异常、多关系保留、方向及路径；接口测试使用 18080/18081 临时服务，测试普通和流式运输、图谱上下文及错误映射，完成后关闭服务。`artifacts/` 保存本地结果，不随源码提交。

依赖范围见 `backend/requirements.txt`；原 Windows 成功验证环境的完整版本快照另存为 `backend/requirements-verified.txt`，其中包含未在发布版启用的历史依赖，因此不是最小运行依赖。

当前没有独立导医接口，也没有账号系统或服务器会话同步功能。需要这些功能时，应另行开发及验证。
